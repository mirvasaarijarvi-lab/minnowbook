# Project rules

- Deno live-test retries honor HTTP Retry-After on 429 responses and retain failure assertions after exhaustion, because short retries cannot outwait the booking cooldown.

- The mobile daily staffing view reuses the full table's filtered slots and time-edit handlers, because permissions, site scope and payroll save tracking must stay identical in both views.

- Subscription checkout validates Stripe HTTPS links and navigates in the same tab, because async popup handoffs can be blocked on mobile.

- Payroll exports use the shared payroll export guard and per-edit save barrier before fetching fresh rows, because a mutation's latest pending state cannot cover overlapping saves or failed edits.

- Keep Lovable email callbacks under `/lovable/email/` authenticated by their own handlers and exempt from app redirects. Edge-function senders send directly through `_shared/managed-email.ts` (no queue), because Lovable's managed delivery owns retries, suppression and unsubscribe.
- Email preview handlers compare secret credentials through the shared server-only timing-safe digest helper, because ordinary string equality can leak matching prefixes.

- Keep one-off application job cadence changes as scoped SQL with adjacent regression tests; do not alter platform-managed email queue functions, because wake/disarm behavior and credentials are maintained by Lovable Cloud.

- Lockfiles (package-lock.json and bun.lock) reference only public registry URLs; after installs run `node scripts/ci/check-npm-lockfile-hygiene.mjs --fix-urls`, because the sandbox cache writes private URLs and CI fails on them.
- New workflows run `./.github/actions/stale-commit-check` right after checkout and are listed in `stale-result-check.yml`, so results from an outdated commit are marked STALE instead of mistaken for the latest code.
- Commit-triggered workflows set `concurrency: {group: <workflow>-${{ github.ref }}, cancel-in-progress: true}`, so a newer push cancels the older run; stale-result-check skips cancelled runs and only marks completed ones.
- SBOM files are regenerated by CI (Dependabot PR refresh + auto-merging PR on main, both using the REPO_PUSH_TOKEN secret); still run `node scripts/generate-sbom.mjs` after dependency changes so PRs pass the SBOM check.
- Keep the transitive seroval security override in both lockfiles and exercise serializer injection regressions, because TanStack uses it for server-to-browser data serialization.
- Keep patched glob and minimatch overrides synchronized in both lockfiles and test cancellation plus spreadsheet round trips, because spreadsheet-export dependencies pull in these filesystem matchers.
- CI lockfile regeneration uses npm 11.21.1 through npx with the public registry across refresh, sync, and audit workflows, because Node 22's bundled npm 10 can crash with a null edgesOut on dependency updates.
- Every business keeps at least one approved owner/admin/superadmin: enforced by the protect_last_tenant_admin trigger on tenant_users (not app code), so every write path, including direct ones and simultaneous changes, is covered.
- Turned-off or deleted accounts are refused on every request: requireAuth/verifyBearer look up the account after verifying the token, and the RLS helpers (is_user_tenant_member, has_tenant_role, is_system_admin, has_permission) call is_account_active, and every RLS-enabled public table has a RESTRICTIVE "Active accounts only" policy for authenticated (new tables must add it too), because signed tokens stay valid for ~1h.
- Workflow steps that retry a command start with `set +e` (or use `shell: bash {0}`), because GitHub's default bash runs with -e and exits on the first failed attempt before any retry runs.
- Live security probes send requests through `src/test/security/cold-start-retry.ts` (fetchWithColdStartRetry, or retryingFetch as the client's global fetch), because a per-attempt timeout plus retry on dropped connections and platform 429/5xx replies keeps cold starts and gateway rate limits from failing correct tests.
