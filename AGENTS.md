# Project rules

- Lockfiles (package-lock.json and bun.lock) reference only public registry URLs; after installs run `node scripts/ci/check-npm-lockfile-hygiene.mjs --fix-urls`, because the sandbox cache writes private URLs and CI fails on them.
- New workflows run `./.github/actions/stale-commit-check` right after checkout and are listed in `stale-result-check.yml`, so results from an outdated commit are marked STALE instead of mistaken for the latest code.
- Commit-triggered workflows set `concurrency: {group: <workflow>-${{ github.ref }}, cancel-in-progress: true}`, so a newer push cancels the older run; stale-result-check skips cancelled runs and only marks completed ones.
- SBOM files are regenerated by CI (Dependabot PR refresh + auto-merging PR on main, both using the REPO_PUSH_TOKEN secret); still run `node scripts/generate-sbom.mjs` after dependency changes so PRs pass the SBOM check.
- Every business keeps at least one approved owner/admin/superadmin: enforced by the protect_last_tenant_admin trigger on tenant_users (not app code), so every write path, including direct ones and simultaneous changes, is covered.
- Turned-off or deleted accounts are refused on every request: requireAuth/verifyBearer look up the account after verifying the token, and the RLS helpers (is_user_tenant_member, has_tenant_role, is_system_admin, has_permission) call is_account_active, because signed tokens stay valid for ~1h.
